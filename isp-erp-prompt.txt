# ISP OPERATIONS ERP

## Master Development Specification for OpenCode

---

# 1. PROJECT OBJECTIVE

Build a production-grade ISP Operations ERP for managing the internal operations of an Internet Service Provider.

This is NOT an ISP AAA/billing platform.

The ERP must NOT implement:

* PPPoE server
* Hotspot
* RADIUS
* Bandwidth authentication
* Internet package management
* Internet speed enforcement
* Router-based subscriber authentication
* MikroTik PPPoE user management
* Retail bandwidth package billing

Those functions are outside the scope of this ERP.

The ERP will focus on:

1. HRM
2. Employee mobile application
3. Facial attendance
4. GPS attendance
5. Employee field tracking
6. Customer/subscriber records
7. Customer location mapping
8. Accounting
9. Operational billing where required
10. Inventory
11. Procurement
12. Field service management
13. Network infrastructure management
14. Fiber network mapping
15. Fiber core management
16. TJ Box management
17. Enclosure management
18. Splitter management
19. OLT/site management
20. Network topology
21. Customer-to-network relationship mapping
22. GIS mapping
23. Reports
24. Notifications
25. Audit logs

The most important differentiator of this ERP is:

> A GIS-based ISP physical network management system capable of managing thousands of customers and thousands of physical network assets.

# 41. GIS-SPECIFIC AI AGENT RULE

Treat GIS and network topology as separate but connected concepts.

GIS answers:

"Where is it?"

Topology answers:

"What is it connected to?"

Never infer network connectivity only from geographic proximity.

Example:

Two fiber cables may physically cross each other but have NO connection.

Therefore:

Physical location ≠ network connection.

All actual connections must be explicitly represented in the database.
